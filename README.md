# 医療法人補助金申請システム

## 1. サービス概要

### 1.1 目的

全国の医療事業者を対象とした、国の補助金申請・審査業務をオンライン化するWebシステムとする。

### 1.2 利用者・提供機能

病院、診療所、その他の対象医療事業者の担当者に対し、以下の機能をオンラインで提供する。

* 補助金申請情報の入力
* 必要書類の提出
* 申請状況の確認

### 1.3 審査業務

行政機関および委託先の審査担当者が、以下の一連の業務をシステム上で実施できるものとする。

* 申請情報の確認
* 不備確認
* 差戻し
* 再申請
* 審査
* 承認

### 1.4 利用特性

補助金申請は年間を通して受け付ける。

四半期末および年度末等の締切時期には申請が集中し、通常時と比較してアクセス数および申請処理件数が大幅に増加することを想定する。

### 1.5 取扱情報

以下の重要情報を取り扱う。

* 事業者情報
* 担当者情報
* 申請内容
* 添付書類
* 審査結果

情報漏えい、不正アクセス、データ改ざん、長時間のサービス停止が発生した場合、事業運営への影響に加え、行政機関としての説明責任が生じる。

### 1.6 基本方針

以下を満たすシステム構成とする。

* 安定したサービス提供
* アクセス集中への対応
* 厳格なアクセス制御
* 操作・変更履歴の追跡
* 障害発生時の原因調査および復旧
* セキュリティインシデント発生時の原因調査および復旧

## 2. サービスの前提条件

### 2.1 利用規模・利用特性

| 項目 | 前提条件 |
| --- | --- |
| 対象地域 | 日本全国（国内のみ） |
| 対象事業者 | 病院、診療所等の医療事業者 |
| 登録事業者数 | 約120,000事業者 |
| 登録ユーザー数 | 約300,000ユーザー |
| 通常時デイリーアクティブユーザー（DAU） | 約30,000人 |
| 繁忙期デイリーアクティブユーザー（DAU） | 約100,000人 |
| 通常時同時接続数 | 約1,000人 |
| ピーク時同時接続数 | 約10,000人 |
| 通常時リクエスト数（RPS） | 50～100 RPS |
| ピーク時リクエスト数（RPS） | 500～1,000 RPS |
| 主な利用時間 | 平日 8:00～20:00 |
| サービス提供時間 | 原則として24時間365日 |
| アクセス集中時期 | 3月、6月、9月および12月の四半期末 |
| 繁忙期アクセス量 | 通常時の5～10倍程度を想定 |

### 2.2 可用性

| 項目 | 前提条件 |
| --- | --- |
| 目標稼働率 | 99.9%以上とする。 |
| アベイラビリティゾーン障害 | 単一のアベイラビリティゾーンに障害が発生した場合も、サービスを継続できる構成とする。 |
| 目標復旧時間（RTO） | 1時間以内とする。 |
| 目標復旧時点（RPO） | 5分以内とする。 |
| バックアップ | データベースおよび重要データを定期的にバックアップする。 |

## 5. 構築・運用方針

TerraformでAWSリソースを管理し、DEV / STG / PRODの環境ごとに構築する。

### 5.1 構築の流れ

1. Terraformの管理基盤を準備する。
2. ECRへアプリケーションのコンテナイメージを登録する。
3. Terraformで変更内容を確認し、AWS環境へ反映する。

### 5.2 運用上の工夫

* **認証**：GitHub ActionsとAWSをOIDCで連携し、アクセスキーの保存を不要にする。
* **更新管理**：インフラはTerraform、アプリケーションは専用のデプロイWorkflowで管理する。
* **コスト管理**：検証時は課金対象リソースの作成を切り替え、費用を抑える。
